Kursus Pembangunan Sistem Dalaman NRES — ASP.NET Core MVC / .NET 10.

Ikut langkah ini mengikut urutan. Setiap arahan ditaip dalam Terminal (atau Developer PowerShell).

1. Pasang perisian asas

Pasang kesemua ini sebelum mula. Semak versi selepas pasang.

Pangkalan data: sesetengah modul guna SQLite (tiada pemasangan — fail sahaja), sesetengah guna SQL Server LocalDB (Windows). Semak appsettings.json modul anda untuk mengetahui yang mana.

2. Sahkan .NET berfungsi

dotnet --version
dotnet --list-sdks

Jika dotnet tidak dikenali, tutup dan buka semula Terminal, atau pasang semula SDK dan mula semula langkah ini.

3. Ambil kod (clone)

Ganti <modul> dengan repo pasukan anda (contoh pematuhan-pks, lapor-diri).

git clone https://github.com/nres-bpm/<modul>.git
cd <modul>
Penting — submodule. Jika projek merujuk klien SSO sebagai submodule, folder itu kosong selepas clone. Jalankan sekali: 
git submodule update --init --recursive
Tanpa langkah ini, dotnet build akan gagal kerana rujukan hilang.

4. Pulih & bina

dotnet restore
dotnet build

Jangkaan: Build succeeded, 0 ralat. Jika gagal, baca ralat pertama — selalunya submodule belum di-init (langkah 3) atau versi SDK salah (langkah 2).

5. Tetapkan konfigurasi untuk dev tempatan

Aplikasi mempunyai safeguard: jika SSO dihidupkan tetapi kunci tiada, ia sengaja gagal mula (mesej "AppKey required"). Untuk pembangunan tempatan, matikan SSO dan Profile supaya aplikasi boot tanpa rahsia.

Dalam appsettings.Development.json, pastikan:

"Nres": {
  "Sso":     { "Enabled": false },
  "Profile": { "Enabled": false }
}

Bila anda perlu menguji SSO / Profile sebenar (dalam rangkaian NRES), barulah hidupkan dan bekalkan rahsia melalui user-secrets — jangan sekali-kali commit rahsia:

dotnet user-secrets init
dotnet user-secrets set "Nres:Sso:AppKey" "<kunci-dev>"
dotnet user-secrets set "Nres:Sso:PrivateKeyPath" "App.key"

6. Sediakan pangkalan data

Pasang alat EF Core sekali sahaja (global):

dotnet tool install --global dotnet-ef

Cipta / kemas kini skema, kemudian isi data contoh (jika modul ada perintah seed):

dotnet ef database update
dotnet run -- seed

Nota: guna hanya data sintetik (rekaan) — jangan guna data NRES sebenar.

7. Jalankan aplikasi

dotnet run

Atau dengan auto-reload semasa menyunting:

dotnet watch

Terminal akan papar alamat, contoh https://localhost:7043. Buka dalam pelayar. Kali pertama HTTPS, percayai sijil dev:

dotnet dev-certs https --trust

Jika modul mendedahkan Web API, halaman Swagger ada di /swagger. Ingat: pada .NET 10, webapi tidak menyertakan Swagger UI secara lalai — ia perlu ditambah (lihat lab API).

8. Aliran kerja Git harian

Mula setiap hari dengan tarik perubahan terkini, kerja atas cabang ciri, kemudian hantar untuk semakan.

git pull --rebase
git switch -c feat/nama-ciri
# ... buat perubahan ...
git add .
git commit -m "ciri: penerangan ringkas"
git push -u origin feat/nama-ciri

Buka Pull Request di GitHub untuk semakan sebelum gabung ke master.

10. Senarai semak sebelum mula membina ciri

  • dotnet --version memaparkan 10.x
  • Repo di-clone dan submodule di-init
  • dotnet build berjaya (0 ralat)
  • appsettings.Development.json: SSO & Profile dimatikan untuk dev
  • Pangkalan data dicipta (dotnet ef database update)
  • Aplikasi berjalan dan boleh dibuka di https://localhost:<port>
  • Cabang ciri sendiri dicipta (git switch -c feat/...)
